# Mockup Studio

Локальная замена платным сервисам мокапов. Открывается в браузере, ничего никуда
не отправляет, видео рендерится и пишется прямо на твоей машине.

## Запуск

```
./start.command
```

Дважды кликни `start.command` в Finder — поднимется сервер и откроется браузер.
Или из терминала: `python3 serve.py`. Порт по умолчанию 8787, занят — возьмёт
следующий свободный.

## Рекламные сценарии

В разделе «4 · Сценарий ролика» — шесть монтажных историй:

| История | Время | Задача |
| --- | --- | --- |
| Запуск | 15 с | Раскрытие устройства, деталь, демонстрация функции, финал |
| Стоп-скролл | 8 с | Быстрый анонс с контрастом крупностей |
| Всё в деталях | 20 с | Корпус, стекло и читаемый проезд по интерфейсу |
| Премьера | 25 с | Размеренная презентация на графитовом фоне |
| Продукт в действии | 30 с | Длинная демонстрация реального сценария использования |
| Бесконечный кадр | 8 с | Замкнутая орбита камеры и света |

Карточка заменяет дорожку сцен и включает автоматическую длительность экспорта.
После конца сценария камера замирает, а видео идёт до конца исходника.
Для более длинной записи можно вручную задать длительность экспорта.
Видео, исходники в IndexedDB, обрезки и наезды сохраняются. При включённом
«Свет и камера» применяются также нейтральная базовая поза, студийный фон,
сдержанные блики и авторская плавность. Отключи переключатель, чтобы оставить
своё оформление. Применение целиком отменяется через `⌘Z`, включая постановку
и длительность экспорта. Существующие наезды продолжают действовать поверх
сценария и могут менять его композицию.

**Продолжение своими кадрами.** Нажми «+ Свой кадр» над таймлайном или
«+ Продолжить своим кадром» в разделе «Положение». Новый блок добавляется
после всех сцен (или в месте плейхеда, если он дальше) и начинается с
финальной позы предыдущего плана. Плейхед переходит в конец нового блока:
задай там размер, поворот и положение телефона ползунками, готовой позой
или мышью. Изменения записываются в конечную позу этого блока, а готовое
начало ролика сохраняет свои ракурсы.

Добавляй следующие кадры той же кнопкой. Между ними камера плавно движется,
после последнего останавливается. «Переход, с» задаёт длительность нового
блока; у существующего её можно менять за край на таймлайне. Клик по своему
блоку открывает его конечную позу для правки. Кадры сохраняются вместе с
проектом, поддерживают отмену/повтор и продлевают экспорт при необходимости.
Видео и его обрезки при этом не меняются.

13 отдельных планов можно добавлять в свободное место таймлайна. Раскрытия
имеют разгон, торможение и финальную выдержку; проезды по интерфейсу мягко разгоняются, идут
равномерно в середине и плавно останавливаются. «Плавность» 100% сохраняет авторскую кривую, 0% делает движение
равномерным. Масштаб интерполируется логарифмически. Случайный дрейф по
умолчанию выключен, а в петле отключён всегда. После финала камера замирает.

Склейки по умолчанию прямые, без обязательного чёрного кадра. У «Премьеры»
перед финалом короткий переход через чёрное (0.24 с). Переключатель «Склейки»
переопределяет стыки всех сцен. Переходы видеодорожки настраиваются отдельно.
Петля замыкает камеру и свет; для полностью бесшовного экспорта необходимо
также зациклить содержимое экрана и использовать статичный фон без зерна.

Проверки: `node --test tests/scenarios.test.cjs` — длительности, камера,
склейки, петля, сохранность медиадорожки и отмена постановки.

## Что умеет

**Телефон — настоящий 3D.** Не картинка-плоскость: корпус имеет толщину, у него
видны торцы со скруглённой фаской и бликами полированного металла. При повороте
виден тот торец, который реально должен быть виден. Толщина регулируется
слайдером.

Лицевая сторона натягивается на перспективный четырёхугольник сеткой
треугольников. Сетка адаптивная: шаг берётся из силы перспективы так, чтобы
ошибка аффинного приближения внутри ячейки держалась около четверти пикселя, а
ячейки остаются квадратными — вытянутая ячейка даёт большую ошибку по своей
диагонали, сколько бы шагов ни было по короткой стороне. Без этого на границе
экрана и вокруг «острова» при наклоне видны ступеньки.

**Кнопки как на живом аппарате.** Слева — короткая Action (6 мм) и две качели
громкости по 12 мм, справа — одна длинная кнопка питания на 24 мм, ровно
напротив обеих кнопок громкости.

Кнопка — слегка выпуклая площадка на торце шириной около 3 мм, со скруглёнными
концами. Никакого паза и никакой обводки: на корпусе нет линейных бортиков, и
рисовать их нельзя. Кнопка отделяется от рамки только светом — блик собран к
середине, а по самым краям площадка уходит в тень.

Две тонкости, на которых легко ошибиться:

- Концы «таблетки» скруглены радиусом в **половину ширины самой кнопки**, а не
  в величину выступа — иначе они выглядят обрубленными. Выступ корпуса идёт по
  тому же профилю: если считать их порознь, на концах кнопки остаётся
  выдвинутый наружу кусок рамки без кнопки на нём, и он читается как чёрная
  полоска.
- Торец заливается частыми полосами, идущими **точно по геометрии** (26 полос
  поперёк толщины, палитра в 129 оттенков), а профиль у него почти плоский:
  выраженные фаски спереди и сзади читаются как два рельса по бокам кнопок.
- Наружу выступает **только площадка кнопки**, а не торец в её зоне: если
  выдвигать торец, получается широкий уступ, на котором лежит овал, и уступ
  читается как бортик.
- У кнопки рисуется **передняя стенка** — иначе спереди она не видна вовсе:
  торец при фронтальном взгляде вырождается в ребро. Выступ берётся с запасом
  (перспектива увеличивает лицевую сторону и съедает часть выступа), кнопки
  рисуются поверх подложки лицевой стороны.
- Блики широкие и мягкие. С резкими (показатели 30 и 60) отражение занимало
  пару градусов: торец вспыхивал из тёмного в белое за один кадр и упирался в
  потолок палитры — кнопка сливалась с торцом. Сейчас худший скачок при
  повороте на градус — 1.4 уровня палитры из 129 вместо 3.9.
- Цвет площадки — это форма (светлый центр, тёмные края относительно торца),
  а не переключатель «светлее/темнее» по порогу: порог давал скачок цвета
  ровно в момент, когда торец пересекал границу яркости. Соблазнительно взять один градиент
  на сегмент — так дешевле, — но его ось задана средней линией сегмента, а
  сечение торца вдоль сегмента меняется; на стыках расхождение переворачивается,
  и торец рассыпается на плитки. Полосы такой ошибки не имеют по построению.
  Соседние полосы кладутся с нахлёстом в обе стороны, иначе между ними
  просвечивает подложка тонкой тёмной линией.

**iPhone 17 из Figma.** Лицевая сторона четырёх моделей — iPhone 17 Pro,
17 Pro Max, 17 и Air — берётся из файла Figma Community, а толщина, торцы и
кнопки по-прежнему считаются в 3D. Так делают все серьёзные мокап-инструменты:
Rotato рендерит настоящие 3D-модели с физически корректными отражениями,
рамочные сервисы кладут PNG поверх скриншота; здесь — гибрид.

Экспорт из Figma приходит сплющенным на фон холста и без альфы, поэтому
прозрачность экрана строится маской по точной геометрии слоёв `Screen` и
`cntr`, а силуэт корпуса — по слою `Br`; радиусы взяты из дизайна. Позиции
кнопок сняты со слоя `Btns`, а не подобраны на глаз.

У каждой модели два цвета: **чёрный** (по умолчанию) и родной из Figma —
у 17 Pro и Pro Max тёмно-синий титан, у 17 и Air серебро. Чёрные варианты
получены обесцвечиванием самих рамок, а не подкраской торца.

Цвет торца снят пипеткой с той же рамки, что и лицевая сторона: если торец
светлее фронта, телефон разваливается на две детали.

Модели: iPhone 17 Pro, 17 Pro Max, 17, Air (рамки из Figma), iPhone 16 Pro, iPhone 16, iPhone 13/14 с чёлкой,
Android с дыркой в экране. Четыре цвета корпуса, Dynamic Island, опциональный статус-бар и блик
стекла.

**Несколько видео на дорожке.** Перетащи в окно сразу несколько файлов или
выбери их в панели — они лягут встык в конец дорожки «видео». Каждый клип
двигается, режется за края (левый край сдвигает точку входа внутри файла,
правый ограничен его длиной) и удаляется крестиком прямо на дорожке или
клавишей Delete. Кнопка «Убрать все видео» чистит дорожку целиком.

**Фото.** На ту же дорожку можно перетащить или выбрать и jpg/png/webp — они
встают клипом на 3 секунды по умолчанию и тянутся за оба края на любую длину
(у фото нет исходной длительности, которая могла бы этому помешать). Звука у
фото нет, стоп-кадра как понятия для него тоже нет — оно и так одно и то же
изображение в любой точке клипа.

Время ведёт плейхед, а не элемент `<video>`: клипов много, между ними бывают
разрывы, и в разрыве активного элемента просто нет. Активный клип
подтягивается перемоткой, когда расхождение больше 0.2 с (0.04 с на паузе —
поэтому скраб плейхедом по дорожке отзывается точно, без видимого рассинхрона
с картинкой). Пока перемотка ещё не долетела, экран держит последний снятый
кадр вместо заглушки — «Привет» показывается только когда на плейхеде вообще
нет ни видео, ни фото. Звук при экспорте сводится через WebAudio со всех
видео-клипов — молчащие в этот момент дают тишину сами.

**Один ролик.** Перетащи файл в окно или выбери в панели. Режимы вписывания
(заполнить / целиком / растянуть), зум и сдвиг внутри экрана. Кнопка
«Убрать видео» возвращает демо-заставку: снимается `src` и вызывается
`load()` — без этого элемент продолжает отдавать последний кадр и рисует его
поверх заставки. Полоса кадров очищается, длина ролика пересчитывается.
Значение file-инпута сбрасывается, иначе выбор того же файла второй раз
не сработает.

**Положение.** Восемь пресетов поз (Фронтально, Герой, Изометрия, На столе,
В руке…) плюс ручные слайдеры. На холсте: тяни мышью — двигать, `Shift`+тяни —
вращать в 3D, колесо — размер.

**Ролики и приёмы.** Готовый ролик — это последовательность сцен с уходом в
чёрное между ними, как снимают промо: раскрытие → детали экрана → герой →
витрина. Четыре ролика на 15–30 секунд кладутся на дорожку одной кнопкой.

Каждая сцена — один приём продуктовой съёмки, срисованный с настоящих
мокап-роликов:

- **Взгляд снизу → общий план** — макро на «острове», глядя на телефон снизу,
  и долгий отъезд.
- **Экран сверху вниз / снизу вверх** — камера вплотную едет по интерфейсу,
  показывая каждую его часть.
- **На столе** — лежит по диагонали и скользит; по стеклу бежит блик.
- **Проезд с разворотом** — слева вполоборота → едет вправо и разворачивается.
- **Снизу с бликом**, **Полуоборот**, **Макро сверху**, **Герой (финал)**.
- **Витрина со светом** — телефон стоит, движется пятно света по студии.

Что делает их «дорогими»: масштаб, поворот и сдвиг меняются одновременно
(одна ось в движении всегда выглядит дёшево), кривая пятого порядка без
толчков на концах, и **зайчик** — отражение источника света, которое
вспыхивает на определённом угле и едет по стеклу вместе с поворотом.
Приёмы кладутся на дорожку в место плейхеда, тянутся и растягиваются
(растянул — тот же проход медленнее). После последней сцены камера замирает,
запись можно продолжать.

**Скорость и плавность под контролем.** Ползунок «Плавность»: 0 — постоянная
скорость, 100 — мягкий разгон и торможение. У мягких кривых пик скорости в
середине почти вдвое выше средней, поэтому на длинных отъездах ставь меньше.
Масштаб интерполируется **логарифмически**: приближение читается глазом как
отношение, а не как разность, и линейный масштаб на отъезде «улетал» в конце —
теперь отношение масштабов на равных отрезках времени постоянно. Кнопки
«Медленнее / Быстрее» растягивают все сцены на дорожке разом, сохраняя порядок.

**Эффекты (каждый выключается).** Глубина резкости — задник размывается, когда
телефон близко. Отражение в полу — телефон зеркалится ниже своей нижней точки с
затуханием и лёгким размытием; только на студийном фоне и пока телефон стоит
(наклон до 30°). Тень под «островом». Засветка — средний цвет экрана ложится на
стекло вокруг него, без этого экран выглядит наклейкой.

**Студийный задник.** Циклорама с мягким пятном света и полом, три пресета.
Свет умеет двигаться по сценарию. На плоском градиенте тот же кадр выглядит
дёшево.

Базовый размер телефона ограничен и высотой, и шириной кадра: иначе один
сценарий в вертикальном формате раздувает телефон во весь экран, а в
горизонтальном оставляет мелким.

**Таймлайн снизу, как в CapCut.** Три дорожки: видео (у каждого клипа своя
плёнка кадров прямо внутри блока), дорожка наездов и блок сценария. Плейхед,
линейка в секундах, кнопки повтора, отмены/повтора и записи прямо там же.

**Масштаб и прокрутка.** Полоса больше не растягивается на весь ролик — у неё
свой масштаб в пикселях на секунду, а длинный ролик просто скроллится вбок.
Это и убирает «прыжки» плейхеда: обрезка или удаление клипа больше не меняют
масштаб всей полосы. Управление — кнопки `−` / `+` / `⤢` в шапке таймлайна
(шаг ×1.25 вокруг плейхеда, `⤢` — «по размеру»), горячие клавиши `-` / `=` /
`0`, колесо мыши на полосе (обычное — прокрутка вбок, с `⌘`/`Ctrl` — зум вокруг
курсора). При первой загрузке видео и при «Убрать все видео» масштаб сам
подгоняется под содержимое; во время монтажа (разделение/обрезка/удаление,
перетаскивание) — никогда сам не меняется.

**Монтаж видеодорожки.** Плейхед внутри клипа — жмёшь `✂ Разделить` (или `S`):
клип режется на два ровно по плейхеду, оба продолжают проигрывать один и тот же
файл без перемотки. `⇤ Отрезать до` (`Q`) и `Отрезать после ⇥` (`W`) обрезают
клип по плейхеду с одной стороны. Всё это работает и на клипе под плейхедом
через кнопки, и на выбранном клипе через панель слева. Удаление клипа
(крестик, `Delete`, кнопка «Удалить клип») **подтягивает** всё, что правее, —
дыры на видеодорожке не остаётся; наезды и сценарий при этом не двигаются, они
привязаны к времени ролика, а не к соседнему клипу. Плейхед во всех этих
операциях следит за содержимым: при разделении и обрезке справа остаётся на
месте, при обрезке слева переезжает на начало клипа (там теперь тот же кадр,
что был под ним), при удалении — едет вместе с подтяжкой или встаёт на начало
удалённого куска, если стоял внутри него.

**Стоп-кадр.** Если удлиняешь клип, а он уже упирается ручкой в конец
исходного файла, — можно тянуть и дальше: хвост клипа просто держит
застывший последний кадр, звука там нет (видео на паузе). Симметрично
слева — тянешь начало клипа за пределы исходника, и он держит первый кадр.
На плёнке эта зона отмечена диагональной штриховкой (в узких клипах —
и подписью «стоп-кадр»); в подписи клипа и в панели слева видно, сколько
секунд стоп-кадра с какой стороны. Обычная обрезка (когда ручка внутри
исходника) работает как раньше.

**Переходы.** Живут в узкой полоске над самими клипами видеодорожки, а не
поверх них — маркер перехода тянется за края, как и клип под ним, а клик по
маркеру открывает настройку длительности. Явная кнопка `◆ Переход` в шапке
таймлайна (или клавиша `T`) ставит затемнение на ближайшем к плейхеду краю
клипа — не нужно попадать мышью в маленький кружок. Кружки `+` тоже остались: на стыке двух клипов, а
теперь ещё и в самом начале первого клипа и в самом конце последнего (чуть
тусклее — это не стык, а затемнение внутрь клипа). На стыке переход выглядит
как крестфейд (уход в чёрное и обратно вокруг границы), в начале или в конце
ролика — как обычное плавное затемнение внутри самого клипа. Длительность —
диапазон 0.1–3с, менять можно четырьмя способами: тянуть узкие ручки прямо по
краям выбранного маркера на дорожке (на стыке — обе, у одиночного края —
только со стороны затемнения); во всплывающей панели, которая появляется над
выбранным маркером; ползунком в панели слева, там же видно, какого вида
переход выбран («на стыке» / «в начале» / «в конце»); клавишами `,` и `.`
(шаг 0.1с). Затемнение между сценами зависит от настройки «Склейки»
и авторского монтажа выбранного ролика.

**Отмена/повтор.** `⌘Z` — отменить, `⌘⇧Z` (или `⌘Y`) — повторить. Работает для
разделения, обрезки, удаления, переходов, наездов и сценария. История держит
до 60 шагов и не переживает перезагрузку страницы.

**Прилипание при перетаскивании.** Края клипов сами примагничиваются к
плейхеду, к началу/концу таймлайна и к границам других клипов — на всех трёх
дорожках. Зажатый `Alt` отключает прилипание для текущего перетаскивания.

**Перестановка клипов на видеодорожке.** Тело клипа (не ручки обрезки) можно
просто тянуть по дорожке, как в CapCut, — соседи больше не останавливают
клип, а меняются с ним местами: когда середина перетаскиваемого клипа
проходит середину соседа, они меняются слотами, промежуток между ними при
этом сохраняется (можно перепрыгнуть сразу нескольких соседей за одно
движение мыши). Отпускаешь — клип встаёт в освободившийся слот, при нехватке
места прижимается к соседу. Наезды и сценарий никак не участвуют в этом
свопе — они остаются на своём времени. Переходы привязаны к клипу и его краю
('in'/'out'), а не к позиции на дорожке, поэтому едут вместе со своим клипом;
если после перестановки клип с переходом на выходе оказался последним на
дорожке, стыка больше нет — переход превращается в затемнение в конце
ролика (это ожидаемое поведение, не баг).

**Блок сценария режется как клип.** Тянешь по времени — сценарий начинается
позже; растягиваешь за края — тот же ролик проигрывается медленнее (на блоке
пишется темп, например `0.70×`); крестик убирает сценарий. До начала блока
камера стоит в стартовой позе сценария, после конца замирает в финальной.

**Повтор.** Кнопка `↻` рядом с плей. Выключена (по умолчанию) — ролик доходит до
конца и останавливается, ничего не перезапускается. Включена — идёт по кругу.

**Наезд на участок экрана.** «+ Наезд» ставит блок на дорожку и сразу
предлагает обвести нужный кусок интерфейса — телефон на это время встаёт ровно.
Дальше блок можно **тянуть по времени, растягивать за края и удалять крестиком**
прямо на дорожке; двойной клик — переобвести участок. Наездов может быть
несколько, пересекаться им не дают. Для выбранного блока настраиваются
плавность входа-выхода (до 6 секунд) и насколько плотно участок заполняет кадр.

Кривая наезда — пятого порядка: на концах у неё нулевая не только скорость, но и
ускорение, поэтому камера трогается и останавливается совсем без толчка.

**Масштаб.** «+ Масштаб» ставит на ту же дорожку блок другого вида: телефон
целиком (не отдельная область экрана, как у наезда) плавно увеличивается и
так же плавно возвращается к исходному размеру. Настраиваются увеличение
(от ×1.05 до ×2.5), сдвиг точки, к которой едет камера, по X и Y (в долях
ширины/высоты кадра, 0 — центр) и та же плавность входа-выхода. Это тот же
блок на той же дорожке наездов — тянуть по времени, растягивать за края,
удалять крестиком и отменять через `⌘Z` можно совершенно так же; отличие
только в том, что двойной клик по нему ничего не делает — обводить у
масштаба нечего.

**Оформление.** Двенадцать пресетов фона плюс свои цвета, mesh-градиент, своя
картинка с размытием, виньетка, зерно, настраиваемая мягкая тень, слой текста
с заголовком и подписью.

**Экспорт.** Форматы кадра под Reels/Shorts, App Store, 4K, OG-картинку или свой
размер. FPS 24/30/60, битрейт до 40 Мбит/с, опционально со звуком. Плюс
сохранение текущего кадра в PNG.

Всё сохраняется в браузере — закрыл и вернулся, всё на месте, включая дорожку
с видео и фото (подробности ниже, в «Сохранении»).

## Сохранение

Весь проект — дорожка с видео и фото, переходы между клипами, наезды, сцена,
оформление и настройки экспорта — хранится в браузере локально, без сервера:
тайминги и настройки лежат в `localStorage`, а сами файлы видео и фото — в
IndexedDB (blob-ссылка на файл не переживает перезагрузку страницы, а сам
файл — переживает, если его хранить отдельно). Закрыл вкладку, перезагрузил
страницу — дорожка и файлы на ней восстанавливаются сами: пока файлы ещё
дотягиваются из IndexedDB, на дорожке уже видны клипы-заглушки, зум таймлайна
подбирается заново под их длину, как при первом добавлении видео.

Кнопка «Убрать все видео» стирает не только дорожку, но и сами файлы из
IndexedDB — вернуть их можно только добавив заново.

Ничего никуда не отправляется — ни файлы, ни настройки не покидают браузер.
Место ограничено тем, что браузер готов выделить под сайт (обычно от
нескольких сотен МБ до нескольких ГБ, зависит от браузера и свободного места
на диске). Если IndexedDB недоступна (приватное окно, отключённое хранилище)
или квота исчерпана — студия предупредит тостом один раз за сессию и просто
не сохранит файл; тайминги и настройки при этом всё равно сохранятся в
localStorage, а сам файл после перезагрузки придётся добавить заново.

## Про формат файла

Студия перед записью **реально проверяет кодеки**, а не верит
`MediaRecorder.isTypeSupported()` — эта функция врёт: часто заявляет mp4 и vp9
как поддерживаемые, а на выходе даёт пустой файл. Проверка занимает полсекунды
при первой записи, результат кэшируется.

Если получился `.webm`, а нужен `.mp4`:

```
./to-mp4.sh ~/Downloads/mockup.webm
```

Вторым аргументом можно задать качество: `18` — почти без потерь, `20` — по
умолчанию, `28` — компактно. Нужен ffmpeg (`brew install ffmpeg`).

## Мелочи

- `?video=demo.mp4` в адресе — сразу загрузить видео из папки проекта.
- Горячие клавиши (работают, если фокус не в текстовом поле):

  | Клавиша | Действие |
  |---|---|
  | `Пробел` | плей/пауза |
  | `S` | разделить клип видео по плейхеду |
  | `Q` | отрезать клип до плейхеда |
  | `W` | отрезать клип после плейхеда |
  | `T` | затемнение на ближайшем крае клипа |
  | `,` / `.` | длительность выбранного перехода −0.1с / +0.1с |
  | `-` / `=` (`_` / `+`) | зум таймлайна вокруг плейхеда |
  | `0` | масштаб таймлайна «по размеру» |
  | `Delete` / `Backspace` | удалить выбранное (наезд → сцена → переход → клип видео) |
  | `⌘Z` | отменить |
  | `⌘⇧Z` / `⌘Y` | повторить |
  | `R` | сбросить положение телефона |
  | `Esc` | выйти из выделения участка / снять выбор перехода |
  | `Alt` при перетаскивании | отключить прилипание к соседним клипам |
- Длина ролика = наибольшее из: длины видео, длины сценария и конца последнего
  наезда при длительности экспорта 0. Готовая история не ограничивает длину исходного видео. Можно задать вручную полем «Длительность» в разделе экспорта.
  Если видео короче ролика, дальше держится его последний кадр — на дорожке
  видно красную метку «конец видео».
- Запись идёт в реальном времени: 30-секундный ролик пишется 30 секунд.
  Не переключай вкладку — браузер останавливает отрисовку холста, и записывать
  становится нечего. Студия это замечает и говорит прямо в результате, а сама
  запись всё равно корректно завершается: её ход ведёт таймер, а не отрисовка.
- Сервер поддерживает HTTP Range. Без этого браузер не умеет перематывать видео,
  и полоса кадров не собирается — штатный `python3 -m http.server` тут не годится.
